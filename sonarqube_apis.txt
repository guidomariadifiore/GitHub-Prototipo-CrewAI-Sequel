DOMAIN: api/applications
Description: Manage applications.
----------------------------------------
ENDPOINT: POST api/applications/add_project
  Description: Add a project to an application.<br/>Requires 'Administrator' permission on the application
  Parameters:
    - application (Required): Key of the application
    - project (Required): Key of the project

ENDPOINT: POST api/applications/create
  Description: Create a new application.<br/>Requires 'Administer System' permission or 'Create Applications' permission
  Parameters:
    - description (Optional): Application description
    - key (Optional): Application key. A suitable key will be generated if not provided
    - name (Required): Application name
    - visibility (Optional): Whether the created application should be visible to everyone, or only specific user/groups.<br/>If no visibility is specified, the default visibility will be used.

ENDPOINT: POST api/applications/create_branch
  Description: Create a new branch on a given application.<br/>Requires 'Administrator' permission on the application and 'Browse' permission on its child projects
  Parameters:
    - application (Required): Application key
    - branch (Required): Branch name
    - project (Required): Project keys. To set several values, the parameter must be called once for each value.
    - projectBranch (Required): Project branches. To set main branch, provide an empty value. To set several values, the parameter must be called once for each value.

ENDPOINT: POST api/applications/delete
  Description: Delete an application definition.<br/>Requires 'Administrator' permission on the application
  Parameters:
    - application (Required): Application key

ENDPOINT: POST api/applications/delete_branch
  Description: Delete a branch on a given application.<br/>Requires 'Administrator' permission on the application
  Parameters:
    - application (Required): Application key
    - branch (Required): Branch name

ENDPOINT: POST api/applications/refresh [INTERNAL]
  Description: Refresh one or all applications.<br/>When a key is not specified, all applications are refreshed.<br/>Requires one of the following permissions:<br/>* 'Administer System' when key is not specified<br/>* 'Administer' rights on the specified application when key is specified
  Parameters:
    - key (Optional): Key: application key.<br/>If not specified, all applications are refreshed.

ENDPOINT: POST api/applications/remove_project
  Description: Remove a project from an application<br/>Requires 'Administrator' permission on the application
  Parameters:
    - application (Required): Key of the application
    - project (Required): Key of the project

ENDPOINT: GET api/applications/search_projects [INTERNAL]
  Description: List projects manually selected in an application.<br/>Requires 'Administrator' permission on the application
  Parameters:
    - application (Required): Application key
    - p (Optional): 1-based page number
    - ps (Optional): Page size. Must be greater than 0 and less or equal than 500
    - q (Optional): Limit search to project names that contain the supplied string.
    - selected (Optional): Depending on the value, show only selected items (selected=selected), deselected items (selected=deselected), or all items with their selection status (selected=all).

ENDPOINT: POST api/applications/set_tags
  Description: Set tags on a application.<br>Requires the following permission: 'Administer' rights on the specified application
  Parameters:
    - application (Required): Application key
    - tags (Required): Comma-separated list of tags

ENDPOINT: POST api/applications/update_branch

DOMAIN: api/ce
Description: Get information on Compute Engine tasks.
----------------------------------------
ENDPOINT: GET api/ce/activity
  Description: Search for tasks.<br> Requires the system administration permission, or project administration permission if component is set.
  Parameters:
    - component (Optional): Key of the component (project) to filter on
    - maxExecutedAt (Optional): Maximum date of end of task processing (inclusive)
    - minSubmittedAt (Optional): Minimum date of task submission (inclusive)
    - onlyCurrents (Optional): Filter on the last tasks (only the most recent finished task by project)
    - p (Optional): 1-based page number
    - ps (Optional): Page size. Must be greater than 0 and less or equal than 1000
    - q (Optional): Limit search to: <ul><li>component names that contain the supplied string</li><li>component keys that are exactly the same as the supplied string</li><li>task ids that are exactly the same as the supplied string</li></ul>
    - status (Optional): Comma separated list of task statuses
    - type (Optional): Task type

ENDPOINT: GET api/ce/activity_status
  Description: Returns CE activity related metrics.<br>Requires 'Administer System' permission or 'Administer' rights on the specified project.
  Parameters:
    - component (Optional): Key of the component (project) to filter on

ENDPOINT: GET api/ce/analysis_status [INTERNAL]
  Description: Get the analysis status of a given component: a project, branch or pull request.<br>Requires the following permission: 'Browse' on the specified component.
  Parameters:
    - branch (Optional): Branch key
    - component (Required): 
    - pullRequest (Optional): Pull request id

ENDPOINT: POST api/ce/cancel [INTERNAL]
  Description: Cancels a pending task.<br/>In-progress tasks cannot be canceled.<br/>Requires one of the following permissions:<ul><li>'Administer System'</li><li>'Administer' rights on the project related to the task</li></ul>
  Parameters:
    - id (Required): Id of the task to cancel.

ENDPOINT: POST api/ce/cancel_all [INTERNAL]
  Description: Cancels all pending tasks. Requires system administration permission. In-progress tasks are not canceled.
  Parameters: None

ENDPOINT: GET api/ce/component
  Description: Get the pending tasks, in-progress tasks and the last executed task of a given component (usually a project).<br>Requires the following permission: 'Browse' on the specified component.
  Parameters:
    - component (Required): 

ENDPOINT: POST api/ce/dismiss_analysis_warning [INTERNAL]
  Description: Permanently dismiss a specific analysis warning. Requires authentication and 'Browse' permission on the specified project.
  Parameters:
    - component (Required): Key of the project
    - warning (Required): Key of the warning

ENDPOINT: GET api/ce/indexation_status [INTERNAL]
  Description: Returns the count of projects with completed issue indexing.
  Parameters: None

ENDPOINT: GET api/ce/info [INTERNAL]
  Description: Gets information about Compute Engine. Requires the system administration permission or system passcode (see WEB_SYSTEM_PASS_CODE in sonar.properties).
  Parameters: None

ENDPOINT: POST api/ce/pause [INTERNAL]
  Description: Requests pause of Compute Engine workers. Requires the system administration permission or system passcode (see WEB_SYSTEM_PASS_CODE in sonar.properties).
  Parameters: None

ENDPOINT: POST api/ce/resume [INTERNAL]
  Description: Resumes pause of Compute Engine workers. Requires the system administration permission or system passcode (see WEB_SYSTEM_PASS_CODE in sonar.properties).
  Parameters: None

ENDPOINT: POST api/ce/set_worker_count [INTERNAL]
  Description: Set the number of workers in the Compute Engine.<br/>If your queue backs up behind analysis reports from large projects, increasing the number of Compute Engine workers will allow you to take full advantage of having configured increased Compute Engine memory on a multi-core server (vertical scaling).<br/>Requires the system administration permission<br/>
  Parameters:
    - count (Required): The number of workers to be used in the Compute Engine. Value must be between 1 and 10.

ENDPOINT: POST api/ce/submit [INTERNAL]
  Description: Submits a scanner report to the queue. Report is processed asynchronously. Requires analysis permission. If the project does not exist, then the provisioning permission is also required.
  Parameters:
    - characteristic (Optional): Optional characteristic of the analysis. Can be repeated to define multiple characteristics.
    - projectKey (Required): Key of project
    - projectName (Optional): Optional name of the project, used only if the project does not exist yet. If name is longer than 500, it is abbreviated.
    - report (Required): Report file. Format is not an API, it changes among SonarQube versions.

ENDPOINT: GET api/ce/task
  Description: Give Compute Engine task details such as type, status, duration and associated component.<br/>Requires one of the following permissions: <ul><li>'Administer' at global or project level</li><li>'Execute Analysis' at global or project level</li></ul>Since 6.1, field "logs" is deprecated and its value is always false.
  Parameters:
    - additionalFields (Optional): Comma-separated list of the optional fields to be returned in response.
    - id (Required): Id of task

DOMAIN: api/webhooks
Description: Webhooks allow to notify external services when a project analysis is done
----------------------------------------
ENDPOINT: POST api/webhooks/create
  Description: Create a Webhook.<br>Requires 'Administer' permission on the specified project, or global 'Administer' permission.
  Parameters:
    - name (Required): Name displayed in the administration console of webhooks
    - project (Optional): The key of the project that will own the webhook
    - secret (Optional): If provided, secret will be used as the key to generate the HMAC hex (lowercase) digest value in the 'X-Sonar-Webhook-HMAC-SHA256' header
    - url (Required): Server endpoint that will receive the webhook payload, for example 'http://my_server/foo'. If HTTP Basic authentication is used, HTTPS is recommended to avoid man in the middle attacks. Example: 'https://myLogin:myPassword@my_server/foo'

ENDPOINT: POST api/webhooks/delete
  Description: Delete a Webhook.<br>Requires 'Administer' permission on the specified project, or global 'Administer' permission.
  Parameters:
    - webhook (Required): The key of the webhook to be deleted, auto-generated value can be obtained through api/webhooks/create or api/webhooks/list

ENDPOINT: GET api/webhooks/deliveries
  Description: Get the recent deliveries for a specified project or Compute Engine task.<br/>Require 'Administer' permission on the related project.<br/>Note that additional information are returned by api/webhooks/delivery.
  Parameters:
    - ceTaskId (Optional): Id of the Compute Engine task
    - componentKey (Optional): Key of the project
    - p (Optional): 1-based page number
    - ps (Optional): Page size. Must be greater than 0 and less than 500
    - webhook (Optional): Key of the webhook that triggered those deliveries, auto-generated value that can be obtained through api/webhooks/create or api/webhooks/list

ENDPOINT: GET api/webhooks/delivery

  Parameters:
    - deliveryId (Required): Id of delivery

ENDPOINT: GET api/webhooks/list
  Description: Search for global webhooks or project webhooks. Webhooks are ordered by name.<br>Requires 'Administer' permission on the specified project, or global 'Administer' permission.
  Parameters:

ENDPOINT: POST api/webhooks/update
  Description: Update a Webhook.<br>Requires 'Administer' permission on the specified project, or global 'Administer' permission.
  Parameters:
    - name (Required): new name of the webhook
    - secret (Optional): If provided, secret will be used as the key to generate the HMAC hex (lowercase) digest value in the 'X-Sonar-Webhook-HMAC-SHA256' header. If blank, any secret previously configured will be removed. If not set, the secret will remain unchanged.
    - url (Required): new url to be called by the webhook
    - webhook (Required): The key of the webhook to be updated, auto-generated value can be obtained through api/webhooks/create or api/webhooks/list
